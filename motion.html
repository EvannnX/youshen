01 / 03 — 先了解，再选择

如何顶起一尊
数字塔骨

整个体验约需一分钟。先选一尊已适配动作的神明，再允许摄像头、站入画面，最后用缓慢而清晰的动作唤起数字塔骨。

01

认清适配状态

只选择标有“可动捕”的神明。其他模型会保留在名单中并显示“适配中”，暂时不能进入实时体验。

02

留出身体空间

面对摄像头站立，让头部、肩膀、手肘、手腕和髋部留在画面中；避免背光与多人入镜。

03

缓慢开始动作

允许摄像头后先保持正面站姿，再缓慢抬臂、转身。动作越稳定，塔骨的回应越清晰。

隐私提示 摄像头画面仅在当前浏览器中用于实时姿态识别，本页不提供录制或上传功能。

PROTOTYPE ARCHITECTURE

实时顶塔骨系统架构

系统以浏览器端实时动捕为核心，把观众的身体动作转译为数字神将的骨骼姿态，并与神明内容库、3D 模型和舞台渲染连接。

01 输入层
USER STATE

观众与神明选择

选择七爷或武判官，确定塔骨身份、动作风格和对应 GLB 模型。

CAMERA STREAM

浏览器摄像头

通过 getUserMedia 获取视频流，作为动作识别和骨架预览的原始输入。

02 感知与分析层
POSE TRACKER

MediaPipe 姿态识别

检测 33 个人体关键点，输出屏幕坐标、世界坐标和关键点可靠性。

CALIBRATION

关键点过滤与校准

判断肩、肘、腕、髋等核心节点是否稳定，降低遮挡和抖动带来的误差。

03 映射与控制层
RETARGETING

人体到塔骨骨骼映射

将人体关节方向转换为神将骨骼旋转，处理镜像、朝向、深度和动作平滑。

MODEL LIBRARY

神明模型与内容库

AvatarLoader 加载 GLB，神明图谱提供身份、造型、仪式角色和动作语义。

04 输出体验层
THREE.JS STAGE

3D 数字塔骨舞台

Three.js 渲染神将模型，实时展示动作同步状态和数字塔骨预览。

EXTENSIONS

展陈扩展接口

后续可接入语音讲解、仪式音效、灯光控制、投影屏幕或数据记录模块。

STATUS FEEDBACK 摄像头权限 / 模型加载 / 动作同步状态
